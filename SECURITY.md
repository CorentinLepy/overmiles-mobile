# Security Policy

Security and privacy are core requirements for OverMiles.

## Reporting a vulnerability

Please **do not open a public GitHub issue** for a security vulnerability, suspected secret exposure, privacy issue, authentication/session weakness, or any report that could put users or data at risk.

Use GitHub's **Private Vulnerability Reporting** for this repository instead:

1. Open the repository's **Security** tab.
2. Choose **Report a vulnerability**.
3. Describe the issue, affected component, reproduction steps, and impact when known.

Please avoid including real user data, access tokens, refresh tokens, API keys, passwords, private documents, or other sensitive material unless it is strictly necessary to understand the report. If evidence contains sensitive data, redact it as much as possible.

## Scope

Reports concerning the OverMiles mobile application, its authentication/session behavior, local encrypted storage, offline synchronization, network communication, privacy boundaries, or interactions with the OverMiles backend are welcome.

For ordinary bugs, crashes, visual regressions, or feature requests that do not involve a security or privacy risk, use the normal issue workflow instead.

## Supported versions

OverMiles is currently in beta. Security fixes are applied to the actively maintained application and current backend rather than to historical builds.

## Disclosure

Please give the project reasonable time to investigate and remediate a reported vulnerability before discussing it publicly. Once a fix is available and disclosure is safe, we can coordinate an appropriate public description when useful.

OverMiles does not currently operate a public bug-bounty program, and submitting a report does not imply a financial reward.
